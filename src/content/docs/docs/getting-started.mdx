## One-command install (macOS · Linux)

```sh
curl -fsSL https://ikenga.dev/install.sh | sh
```

The script detects your OS and architecture, downloads the matching artifact from the latest GitHub Release, and installs it:

- **macOS** — mounts the universal `.dmg` (**~40 MB**) and copies `Ikenga.app` into `/Applications`. Ikenga is not yet code-signed, so if macOS shows a Gatekeeper warning the first time you open it, the script prints how to open it anyway (right-click → Open, or System Settings → Privacy & Security → Open Anyway).
- **Linux** — defaults to the system-wide `.deb` (**~22 MB**) when `dpkg` is present, printing the single `sudo apt-get install` line to paste; otherwise it installs the no-sudo AppImage (**~110 MB**) to `~/.local/bin/ikenga` and makes it executable. Force either with `IKENGA_FORMAT=deb` or `IKENGA_FORMAT=appimage`. Both download from GitHub's release CDN, which can run slowly — **give the transfer a minute or two before assuming it stalled.**

### macOS — Apple Silicon and Intel

Releases ship a single universal `.dmg` that runs natively on both Apple Silicon (arm64) and Intel (x86_64), so the install script downloads the same file on either chip. Like the other installers it is not yet code-signed; if macOS shows a first-run Gatekeeper warning, approve it once: right-click the app and choose Open, or go to System Settings → Privacy & Security and click Open Anyway.

## Download and inspect (the no-`curl | sh` path)

If you'd rather not pipe a script straight into your shell, you don't have to.

1. Open the [latest release](https://github.com/ikenga-hq/ikenga/releases/latest) and download the artifact for your platform directly — `.dmg` (macOS), `.AppImage` or `.deb` (Linux), `.exe` (Windows).
2. To read the installer before running it:

   ```sh
   curl -fsSL https://ikenga.dev/install.sh -o install.sh
   less install.sh        # read it
   sh install.sh          # then run it
   ```

3. Each release (from 0.19.1) includes a `SHA256SUMS.txt` that lists the SHA-256 of every asset: download it next to your installer and run `shasum -a 256 -c SHA256SUMS.txt --ignore-missing` (macOS) or `sha256sum -c SHA256SUMS.txt --ignore-missing` (Linux). GitHub also shows each asset's digest on the release page, and the Linux, Windows and updater archives ship minisign `.sig` files.

## Server (Linux, beta)

From 0.19.4, each release also attaches the headless server for Linux: `ikenga-server_<version>_linux_amd64.tar.gz` and `_arm64.tar.gz`, each with a `.sigstore.json` bundle and listed in `SHA256SUMS.txt`. Check a download with `sha256sum -c SHA256SUMS.txt --ignore-missing` and `gh attestation verify <file> --repo ikenga-hq/ikenga`. The tarball holds `bin/ikenga-server`, the web app in `dist/` and the systemd units; setup steps are in the server README in the [ikenga repository](https://github.com/ikenga-hq/ikenga/tree/main/scripts/server). The server is beta: you install and run it yourself, and pairing a phone needs HTTPS in front.

## Windows

Download the `.exe` installer (**~17 MB**) directly from the [latest release](https://github.com/ikenga-hq/ikenga/releases/latest). The installer is not yet code-signed, so Windows shows a first-run warning.

## Environment overrides

The install script honours five environment variables:

| Variable | Default | Purpose |
| --- | --- | --- |
| `IKENGA_VERSION` | `latest` | Pin a specific release tag (e.g. `<version>`). |
| `IKENGA_FORMAT` | `deb` if `dpkg` present, else `appimage` | Linux installer format. `deb` is the smaller (~22 MB) system-wide install (needs sudo); `appimage` is the larger (~110 MB) no-sudo portable build. |
| `IKENGA_INSTALL_DIR` | `~/.local/bin` | Linux portable (AppImage) install location. Ignored when `IKENGA_FORMAT=deb`. |
| `IKENGA_REPO` | `ikenga-hq/ikenga` | Source repository. |
| `IKENGA_SILENT` | `0` | Windows: set to `1` to run the NSIS installer silently (`/S`) with no UI. |

Example — pin a version and install to a different directory:

```sh
curl -fsSL https://ikenga.dev/install.sh | \
  IKENGA_VERSION=<version> IKENGA_INSTALL_DIR=$HOME/opt/bin sh
```

## Offline / air-gapped install

Ikenga's built-in pkg system uses [Bun](https://bun.sh) as its JavaScript runtime. On a normal first launch the shell fetches the pinned Bun release in the background — a small status chip in the shell chrome shows download progress — and the rest of the app is fully usable while the transfer completes. Nothing blocks startup.

If you are on a restricted network, or simply prefer to supply your own binary, three escape hatches are available.

### Option 1 — use a system Bun

Install Bun yourself (see [bun.sh/docs/installation](https://bun.sh/docs/installation)) and make the `bun` binary available on your `$PATH`. At startup the shell detects it, checks the version, and uses it if the version meets or exceeds the pinned minimum (currently **1.3.14**). No download occurs.

```sh
# Verify Bun is on PATH and meets the minimum version
bun --version   # must be >= 1.3.14
```

### Option 2 — drop a binary in the data directory

Copy a Bun binary directly into the location the shell checks:

| Platform | Path |
| --- | --- |
| macOS | `~/Library/Application Support/app.ikenga/bun/<target>/bun` |
| Linux | `~/.local/share/app.ikenga/bun/<target>/bun` |
| Windows | `%APPDATA%\app.ikenga\bun\<target>\bun.exe` |

Where `<target>` matches your platform:

| Platform | `<target>` |
| --- | --- |
| macOS Apple Silicon | `darwin-aarch64` |
| macOS Intel | `darwin-x64` |
| Linux x64 | `linux-x64` |
| Linux arm64 | `linux-aarch64` |
| Windows x64 | `windows-x64` |

The shell validates the file's SHA-256 against its pinned checksum. If the checksum does not match, the binary is rejected and a background fetch is attempted instead.

### Option 3 — `IKENGA_BUN_PATH` environment variable

Set `IKENGA_BUN_PATH` to the absolute path of any `bun` binary before launching the shell:

```sh
IKENGA_BUN_PATH=/opt/bun/bin/bun ikenga
```

A binary provided this way is **trusted without checksum verification** — you are asserting that you control the binary. It takes precedence over all other resolution paths. The variable is not read by the install script; set it in your shell profile (`.bashrc`, `.zshrc`, etc.) or via a `.env` file if your deployment platform supports one.

<Aside type="note" title="Which path was chosen?">
Open the shell's log viewer (**Ctrl+Shift+L** / **⌘⇧L**) and filter for `runtime` to see which Bun resolution path the shell selected at startup.
</Aside>

## First launch

Open Ikenga. On first run, an onboarding wizard guides you through setup across seven steps:

1. **Welcome** — an introduction to the workspace.
2. **Engine** — set up your agent engine. Ikenga is engine-optional — the shell boots and runs without one — but you will want an engine configured to run agent sessions. Claude Code is fully wired; Codex is a pluggable adapter. Each engine needs its CLI on your `$PATH` and its own auth (for example, `claude login` for Claude Code).
3. **Project** — choose or add your project folder.
4. **Store** — browse Ngwa to discover available apps and extensions.
5. **Look** — configure your preferred theme and appearance.
6. **Shortcuts** — review essential keyboard shortcuts.
7. **Done** — finish setup and land in your project home (Obi).

From here:

- Install the **`ikenga` CLI** — ensure Bun is on your `$PATH`, then install with `npm i -g @ikenga/cli`. Note that the in-app store (Ngwa) is the main way to install apps; the CLI is available for managing packages on disk (`ikenga list`, `ikenga add <pkg>`). See **[Pkgs →](/docs/pkgs)**.
- Build your own pkg — start with the **[Build your first pkg](/docs/build-a-pkg)** tutorial.
- Drive a running shell from the terminal with the **`iyke` CLI** and **[mcp-iyke](/docs/mcp-iyke)**.
